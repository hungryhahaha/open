# 브리프 코치 — 임원 1:1 구두 보고 리허설

휴대폰에서 소리 내어 보고를 연습하면, 코치가 **끝까지 다 들은 뒤** 구조·억양·강세·속도를 짚어 주고,
고쳐서 다시 말하면 **지난번과 비교**해 주는 웹앱입니다. 설치 없이 브라우저에서 열리고, 홈 화면에 추가하면 앱처럼 씁니다.

```
준비(상황·결론·원고) → 연습(실시간 억양 곡선·힌트, 시간 제한 없음, 일시정지 가능)
   → 피드백(점수 4축 · 고칠 3가지 · 문장별 전달 지도 · AI 심층 코칭)
   → 포커스 반영해 다시 연습 → 지난 연습과 비교 → 기록(점수 추이)
```

## 1. 휴대폰에서 여는 방법

마이크는 **https 주소**에서만 켜집니다. 아래 중 하나로 여세요.

| 방법 | 억양·강세 분석 | 받아 적기 | AI 코치 | 준비 |
|---|---|---|---|---|
| **GitHub Pages** (권장) | ✓ 실시간 | ✓ OpenAI(녹음 후) 또는 브라우저 | OpenAI(또는 Claude) API 키 | 공개 저장소 + Pages 설정 1회 |
| **정적 호스팅** (Netlify Drop 등) | ✓ 실시간 | ✓ | OpenAI(또는 Claude) API 키 | `brief-coach` 폴더를 끌어다 놓기 |
| **claude.ai 아티팩트 링크** | 녹음 파일 업로드 시만 | Chrome 탭에서만 | ✓ 키 없이 claude.ai 계정 | 없음 |

### 이 저장소에서의 배포

`main`에 반영되면 저장소의 Pages 배포(`ai-brief-pages.yml`, 그리고 매일 아침의 `ai-brief.yml`)가 이 폴더를
사이트의 `/brief-coach/` 경로에 함께 올립니다. 따로 설정할 것은 없습니다.

- 주소: **https://hungryhahaha.github.io/open/brief-coach/**
- 공개되는 것은 앱 코드뿐입니다. 연습 기록과 API 키는 각자의 휴대폰 브라우저에만 저장됩니다.

### Android 휴대폰에 설치

1. Chrome으로 위 주소를 엽니다.
2. 메뉴(⋮) → **앱 설치**(또는 홈 화면에 추가). 이후 홈 화면 아이콘으로 앱처럼 열립니다.
3. 앱 오른쪽 위 설정 → AI 연결 → **OpenAI API 키**(필요하면 Anthropic 키도)를 넣고 `연결 확인`. 코칭 모델은 GPT-6.1 Terra가 기본이며 GPT-6 Luna(가성비)부터 Astra·Claude Fable 5.2(최고 사양)까지 고를 수 있습니다.
   키는 OpenAI 플랫폼(platform.openai.com)의 API keys에서 발급하고, Billing에 크레딧을 넣어야 동작합니다. Limits에서 월 사용 한도를 걸어 두세요.
4. 설정 → **기기 점검(10초)**: "하나, 둘, 셋…"을 말하면 마이크(억양 분석)와 OpenAI 받아 적기가 둘 다 되는지 확인합니다.
5. 처음 녹음할 때 Chrome이 마이크 권한을 물으면 **허용**을 누릅니다. 거부했다면 주소창 왼쪽 아이콘 → 권한 → 마이크에서 바꿀 수 있습니다.

> 받아 적기·AI 코칭·낭독은 인터넷이 필요합니다. 억양 분석과 내장 코치는 한 번 열어 둔 뒤에는 인터넷 없이도 동작합니다.

## 2. 쓰는 법

1. **준비**: 듣는 사람·목적·목표 시간·언어(한국어/English)를 고르고, 결론 한 문장과 요청 사항을 적습니다(선택).
   원고가 있으면 `강세·쉼 자동 표시`로 가이드 스크립트를 만들거나, `말하기 전에 원고 점검`으로 내용부터 봅니다.
2. **연습**: 가운데 버튼을 누르면 3초 준비 후 듣기 시작합니다. 시간 제한은 없고, 일시정지한 시간은 재지 않습니다.
   말하는 동안 억양 곡선과 속도·억양 폭·음량이 보이고, 끝 올림·말끝 흐림·과속 같은 신호가 짧게 뜹니다(설정에서 끌 수 있음).
3. **피드백**: `완료`를 누르면 바로 내장 코치 결과가 나오고, AI 코치가 연결돼 있으면 20~60초 뒤 심층 피드백이 붙습니다.
   - 점수 4축: 구조·메시지 / 억양·강세 / 속도·쉼 / 언어 습관. AI 검토가 있으면 AI가 매긴 점수가 최종이고, 점수마다 **AI 이유**와 **측정 근거**를 한 줄씩 보여 줍니다
   - 다음 연습에서 고칠 3가지: 왜 중요한지, 어떻게 고치는지, 다음 시도 전 30초 연습법
   - 문장별 전달 지도: 문장마다 끝 억양(↘ ↗ ⤓), 강세가 실린 단어, 강세가 빠진 숫자·핵심어, 군말·흐리는 표현, 구간 다시 듣기
   - AI 코치: 임원 관점 한 줄 평가, 문장별 억양 지시, 30초 오프닝 재작성, 모범 스크립트(바로 가이드로 연습·낭독 듣기), 예상 질문
   - 음성 인식이 틀렸으면 `받아 적은 내용 고치기`로 고친 뒤 다시 분석합니다.
4. **포커스 반영해서 다시 연습**: 연습 화면 위에 지난번 포커스 3가지가 뜨고, 끝나면 `지난 연습과 비교`에서 항목별로
   개선·일부 개선·아직을 알려 줍니다. `기록` 탭에서 점수 추이를 봅니다.

## 3. 점수 매기는 법

**AI 검토가 있으면 점수와 코멘트 전체를 AI가 씁니다.** AI는 받아 적은 글과 기기 측정값(억양·말끝·강세·속도·쉼)을 함께 보고
축마다 0~100점과 이유를 매기며, 그 점수가 최종 점수입니다. 기기 측정 점수는 각 점수 아래 "측정" 줄에 근거로 남습니다.
AI 검토가 없거나 아직 진행 중이면 기기 측정과 규칙으로 만든 간이 점수를 보여 주고, 그렇다고 화면에 표시합니다.

| 축 | AI가 보는 것 | 측정 근거(예) | 종합 반영 |
|---|---|---|---|
| 구조·메시지 | 첫 30초 결론, 근거의 숫자, 논리 흐름, 명확한 요청 | 첫 30초 결론 · 숫자 개수 · 구조 표지 · 마지막 요청 · 리스크 · 길이/목표 | 30% |
| 억양·강세 | 문장 끝 하강, 말끝 유지, 강세 위치, 억양 폭 | 끝 내림/올림 · 말끝 흐림 · 억양 폭 · 핵심어 강세 | 30% |
| 속도·쉼 | 속도, 쉼, 연속 발화 | 음절/분 · 쉼 비율 · 최장 연속 발화 | 20% |
| 언어 습관 | 군말, 흐리는 표현, 종결, 문장 길이 | 군말 분당 · 흐리는 표현 · '~습니다' 종결 · 긴 문장 | 20% |

- 측정값이 없는 축(예: 원고 점검의 억양·속도)은 점수를 매기지 않습니다.
- 지난 연습과의 비교·기록 탭의 추이도 최종 점수를 씁니다.

### 피드백 화면 (AI 검토가 있을 때)

총평(한 줄 평가 + 3~4문장 + 다음 시도에 집중할 한 가지) → 지난 연습과 비교 → 고칠 3가지 → 잘한 점 →
문장별 코멘트(문장마다 AI의 좋음/고칠 점 코멘트와 고쳐 말할 문장, 들어 보기) → AI 제안(30초 오프닝, 모범 스크립트, 예상 질문) →
기기 측정 상세(접힘: 측정 점수와 근거, 내장 코치의 규칙 진단).

## 4. 무엇을 어떻게 재는가

모든 음향 분석은 **기기 안에서** 합니다(Web Audio). 받아 적기는 브라우저의 음성 인식(Chrome은 Google 음성 서비스, Safari는 Apple)을 씁니다.

| 항목 | 방법 | 기준 |
|---|---|---|
| 높낮이 | 43 ms 프레임마다 YIN 기본주파수 추정, 말한 사람 평균 대비 반음(st) | 억양 폭(p10~p90) 4.5~12반음 |
| 끝 억양 | 문장 마지막 0.2~0.45초의 높이 변화와 기울기 | +1.5반음 이상 상승 = 끝 올림 ↗ |
| 말끝 흐림 | 마지막 0.3초 음량 vs 문장 상위 25% 음량 | 10 dB 이상 하락 = ⤓ |
| 강세 | 문장 중간값보다 2.2반음 이상 높고 음량 상위 40%인 국소 최고점 → 음절 비례로 단어에 대응(추정) | 숫자·핵심어 ±1단어 안에 강세 |
| 쉼·연속 발화 | 0.25초 이상 무음 = 쉼, 0.4초 미만 쉼으로 이어진 구간 = 연속 발화 | 쉼 비율 12~32%, 최장 연속 8초 이하 |
| 속도 | 받아 적은 글의 음절 수 ÷ (생각하느라 멈춘 시간을 뺀) 말한 시간 | 한국어 260~335 음절/분, 영어 130~168 단어/분 |
| 언어 습관 | 군말(어·음·이제·좀·약간…), 흐리는 표현(~것 같습니다·아마·혹시…), '~요'·열린 종결, 연결어미 3개 이상의 긴 문장 | 군말 분당 1회 이하, 흐리는 표현 0회 |
| 구조 | 첫 30초(첫 3문장) 안의 결론, 뒤 30%의 요청 표현, 구조 표지(첫째·세 가지), 숫자, 리스크·대응, 준비한 결론 키워드 반영률, 목표 시간 | 첫 30초에 무슨 건이고 결론인지 → 근거 → 리스크 → 요청 |

측정값은 휴대폰 마이크 기준 근사치입니다. 강세 위치는 받아 적은 글과 소리의 시간 비율로 추정하므로 ±1단어 정도 어긋날 수 있습니다.

### 첫 30초 점검

임원이 첫 30초 안에 무슨 건이고 결론이 무엇인지 알 수 있는지를 봅니다. 결론이 첫 문장에 없다는 이유만으로는 지적하지 않습니다.

- 범위: 구두 보고는 첫 3문장(문장부호 없는 받아 적기는 말끝으로 문장을 나누고, 30초 분량을 넘는 긴 문장은 그 지점에서 자름), 문서는 첫 장의 제목과 첫 문단(또는 요약).
- 통과: 범위 안에 결론이 있음. 앞에 맥락 1~2문장(무슨 건인지, 왜 지금 보고하는지)이 있어도 됩니다. 준비 화면에 결론 한 문장을 적었다면 범위 안의 결론이 그 결론과 같아야 합니다.
- 지적: 경위·진행 과정·새로운 정보가 나열되어 결론이 범위 밖으로 밀린 경우, 맥락만 있고 결론이 없는 경우.
- 예외: 주제를 처음 듣는 청자, 나쁜 소식, 시연처럼 맥락이 길어야 할 때도 범위 안에 "결론은 ○○이고, 이유를 보여 드리겠습니다" 같은 예고가 있으면 통과입니다("결론은 나중에 말씀드리겠습니다"처럼 결론 없는 예고는 통과가 아님).
- 지적할 때 문제 칸: `30초 안에 전달되는 내용: ○○ / 실제 결론: ○○`
- AI 리뷰 프롬프트의 [점검 기준]에도 같은 기준이 들어 있어 AI 코칭도 같은 방식으로 판단합니다.

## 5. AI 연결 · 모델 선택 (2026년 11월 기준)

설정 → AI 연결에 OpenAI 키와 Anthropic 키를 각각 넣고(둘 중 하나만 있어도 됨) 코칭 모델을 고릅니다.
키는 그 기기 브라우저(localStorage)에만 저장되고 해당 회사 API로만 전송됩니다. 가격은 입력/출력 100만 토큰당 참고 가격입니다.

**코칭 모델**

| 구분 | 모델 | API ID | 등급 | 참고 가격 |
|---|---|---|---|---|
| GPT | GPT-6 Astra | `gpt-6-astra` | 최고 사양 | $10 / $50 |
| GPT | GPT-6.1 Sol | `gpt-6.1-sol` | 고사양 | $2 / $10 |
| GPT | **GPT-6.1 Terra** | `gpt-6.1-terra` | 균형 · 기본값 | $1 / $5 |
| GPT | **GPT-6 Luna** | `gpt-6-luna` | 가성비 | $0.10 / $0.50 |
| Claude | Claude Fable 5.2 | `claude-fable-5-2` | 최고 사양(답이 오래 걸릴 수 있음) | $8 / $40 |
| Claude | Claude Opus 5.5 | `claude-opus-5-5` | 고사양 · Claude 권장 | $4 / $20 |
| Claude | Claude Sonnet 5.5 | `claude-sonnet-5-5` | 균형 | $2 / $10 |
| Claude | Claude Haiku 5.5 | `claude-haiku-5-5` | 가성비 | $0.10 / $0.50 |
| Claude | Claude Opus 5 / Sonnet 5 | `claude-opus-5` / `claude-sonnet-5` | 이전 세대 | $5 / $25, $2 / $10 |

- `연결 확인`을 누르면 그 키로 실제 쓸 수 있는 모델 목록을 읽어, 목록에 없는 모델에는 "이 키로 확인 안 됨"을 붙입니다. OpenAI 키로 쓸 수 있는 다른 GPT 모델도 아래에 함께 보여 줍니다.
- 고른 GPT 모델을 그 키로 쓸 수 없으면 쓸 수 있는 모델(Terra → Luna → Sol → Astra 순)로 바꿔 검토하고 알려 줍니다.
- GPT는 Responses API + JSON 스키마(strict), 분석 깊이 = reasoning effort. Claude는 Messages API + JSON 출력, 분석 깊이 = effort이며, Fable 5.2·Opus 5.5·Opus 5·Sonnet 5.5에는 정책상 거절 시 다른 모델로 이어 받는 서버측 대체(`fallbacks: "default"`)를 켭니다.

**음성 — 받아 적기(STT)와 낭독(TTS)**

Claude API에는 음성 인식·발화 기능이 없어, 코칭을 Claude로 해도 음성은 아래에서 고른 OpenAI 모델(OpenAI 키 필요)이나 브라우저·기기 기능을 씁니다.

| 기능 | 선택지 |
|---|---|
| 받아 적기 | **GPT Transcribe** `gpt-transcribe`(최신·기본) · GPT-4o Transcribe · GPT-4o mini Transcribe(가성비) · Whisper `whisper-1`(문장 시간 정보) · 브라우저 실시간 받아 적기(무료) |
| 낭독 | GPT-4o mini TTS `gpt-4o-mini-tts-2025-12-15`(최신·기본) · `gpt-4o-mini-tts` · TTS-1 HD · TTS-1(둘 다 낭독 지시 없음) · 기기 음성(무료) |

- 받아 적기는 녹음이 끝난 뒤 녹음 파일을 보냅니다(파일당 25MB까지). 키가 고른 모델을 못 쓰면 `gpt-transcribe` → `gpt-4o-transcribe`로 바꾸고 기억합니다.
- OpenAI 안내상 현재 낭독 모델(`gpt-4o-mini-tts` 계열, `tts-1` 계열)은 2027년 1월 6일 종료 예정이고, 후속은 Realtime API 전용(`gpt-realtime-2.1-mini`)입니다. 낭독이 실패하면 자동으로 기기 음성으로 읽습니다.
- **보내는 것**: OpenAI 받아 적기를 쓰면 녹음 소리가, 코칭에는 받아 적은 글·측정값·보고 상황·지난 시도 요약이, 낭독에는 스크립트 글이 전송됩니다.
- 회사망에서 `api.openai.com`·`api.anthropic.com`이 막혀 있으면 내장 코치와 억양 분석만 동작합니다.

## 6. 알려진 제약

- **Android Chrome**: 음성 인식이 말이 끊길 때마다 다시 시작되며 짧은 알림음이 날 수 있습니다.
- **일부 기기**에서는 받아 적기와 억양 분석이 마이크를 동시에 못 쓸 수 있습니다. 설정 → `기기 점검`이 이를 확인해
  `억양 분석만`(내용은 원고 기준 또는 끝난 뒤 직접 적기)이나 `받아 적기만`으로 자동 전환합니다.
- **claude.ai 화면 안**에서는 마이크 소리를 직접 받을 수 없어 실시간 억양 분석이 꺼집니다. 녹음 앱으로 녹음한 파일을
  연습 화면 맨 위 `녹음 파일 고르기`로 올리면 억양·강세·속도를 분석합니다.
  - 읽는 형식: m4a(AAC)·mp3·wav·webm 등 브라우저가 재생하는 형식. `.amr`·`.3gp`는 브라우저가 읽지 못합니다.
  - iPhone 음성 메모는 ··· → "파일에 저장" 후 고르면 됩니다.
  - 파일에는 글이 없으므로, 올린 뒤 `녹음에서 말한 내용 적기`에 말한 내용을 적으면 구조·언어 습관과 강세 위치까지 평가합니다.
  - Claude 앱 안에서 버튼을 눌러도 파일 선택 창이 뜨지 않으면 같은 링크를 Chrome·Safari에서 여세요.
- 연습 기록은 기기 브라우저에만 남고, 녹음 소리는 저장하지 않습니다(화면을 닫으면 사라짐).

## 7. 개발

```bash
node --test brief-coach/tests/core.test.mjs
```
